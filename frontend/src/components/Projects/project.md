# Работа с проектами - API документация

## Обзор
API для управления проектами, рабочими пространствами и участниками. Проекты позволяют организовать совместную работу над задачами с разделением на рабочие пространства.

## Базовые концепции

### Иерархия объектов:
1. **Проект** - основной контейнер для совместной работы
2. **Рабочее пространство (Workspace)** - подраздел проекта для конкретных задач
3. **Участник (Participant)** - пользователь, участвующий в проекте/рабочем пространстве
4. **Чат** - средство коммуникации для проекта/рабочего пространства

### Статусы участников:
- `owner` - владелец (полный доступ)
- `admin` - администратор
- `editor` - редактор
- `viewer` - наблюдатель (только чтение)

### Статусы проектов:
- `active` - активный
- `archived` - архивный
- `completed` - завершённый

## Аутентификация
Все операции с проектами требуют аутентификации через OAuth2 Password Bearer токен.

## Эндпоинты

### 1. Управление проектами

#### 1.1 Создание проекта
**POST** `/projects/`

**Тело запроса (ProjectCreate):**
```json
{
  "name": "Название проекта",
  "description": "Описание проекта",
  "tags": ["tag1", "tag2"],
  "create_channel": true,
  "create_chat": true,
  "avatar_file_id": "uuid-аватара"
}
```

**Ответ (201 Created):**
```json
{
  "id": "uuid-проекта",
  "name": "Название проекта",
  "description": "Описание проекта",
  "tags": ["tag1", "tag2"],
  "created_by": 123,
  "status": "active",
  "created_at": "2024-01-01T10:00:00Z",
  "updated_at": "2024-01-01T10:00:00Z",
  "creator": {...},
  "workspaces": [...],
  "participants": [...]
}
```

#### 1.2 Получение списка проектов пользователя
**GET** `/projects/`

**Параметры запроса:**
- `status` - фильтр по статусу (active/archived/completed)
- `tags` - фильтр по тегам (массив строк)
- `search` - поиск по названию/описанию
- `limit` - количество проектов на странице (1-100, по умолчанию 20)
- `offset` - смещение для пагинации

**Ответ:**
```json
[
  {
    "id": "uuid-проекта",
    "name": "Название",
    "description": "Описание",
    "status": "active",
    "created_at": "2024-01-01T10:00:00Z",
    "updated_at": "2024-01-01T10:00:00Z",
    "participant_count": 5,
    "unread_messages_count": 3
  }
]
```

#### 1.3 Получение информации о проекте
**GET** `/projects/{project_id}`

**Параметры:**
- `project_id` - UUID проекта

**Ответ:** Полная информация о проекте включая рабочие пространства и участников

#### 1.4 Обновление проекта
**PATCH** `/projects/{project_id}`

**Тело запроса (ProjectUpdate):**
```json
{
  "name": "Новое название",
  "description": "Новое описание",
  "status": "completed",
  "tags": ["new-tag"]
}
```

#### 1.5 Архивация проекта
**DELETE** `/projects/{project_id}/archive`

Архивирует проект (меняет статус на archived)

#### 1.6 Выход из проекта
**DELETE** `/projects/{project_id}/leave`

Удаляет текущего пользователя из участников проекта

### 2. Управление рабочими пространствами

#### 2.1 Создание рабочего пространства
**POST** `/projects/{project_id}/workspaces`

**Тело запроса (WorkspaceCreate):**
```json
{
  "name": "Название workspace",
  "description": "Описание",
  "create_chat": true
}
```

**Ответ (201 Created):**
```json
{
  "id": "uuid-workspace",
  "name": "Название",
  "description": "Описание",
  "project_id": "uuid-проекта",
  "is_main": false,
  "created_at": "2024-01-01T10:00:00Z",
  "chat": {...},
  "participants": [...]
}
```

#### 2.2 Получение списка рабочих пространств проекта
**GET** `/projects/{project_id}/workspaces`

#### 2.3 Обновление рабочего пространства
**PATCH** `/projects/workspaces/{workspace_id}`

**Тело запроса (WorkspaceUpdate):**
```json
{
  "name": "Новое название",
  "description": "Новое описание"
}
```

#### 2.4 Удаление рабочего пространства
**DELETE** `/projects/workspaces/{workspace_id}`

### 3. Управление участниками

#### 3.1 Добавление участников в проект
**POST** `/projects/{project_id}/participants`

**Тело запроса (ParticipantAdd):**
```json
{
  "user_ids": [123, 456, 789]
}
```

**Ответ (201 Created):** Список добавленных участников

#### 3.2 Получение списка участников проекта
**GET** `/projects/{project_id}/participants`

#### 3.3 Обновление статуса участника проекта
**PATCH** `/projects/{project_id}/participants/{participant_user_id}`

**Тело запроса (ParticipantUpdate):**
```json
{
  "status": "admin"
}
```

#### 3.4 Добавление участников в рабочее пространство
**POST** `/projects/workspaces/{workspace_id}/participants`

#### 3.5 Получение списка участников рабочего пространства
**GET** `/projects/workspaces/{workspace_id}/participants`

#### 3.6 Удаление участника из рабочего пространства
**DELETE** `/projects/workspaces/{workspace_id}/participants/{participant_user_id}`

## Особенности работы

### Автоматическое создание чатов
При создании проекта/workspace можно указать:
- `create_chat: true` - создаст чат для общения
- `create_channel: true` - создаст канал для уведомлений

### Основное рабочее пространство
При создании проекта автоматически создаётся основное рабочее пространство (`is_main: true`).

### Наследование участников
Участники проекта автоматически добавляются во все рабочие пространства проекта.

### Права доступа
- Только `owner` может удалять проект
- `owner` и `admin` могут добавлять/удалять участников
- `editor` может редактировать контент
- `viewer` имеет доступ только на чтение

## Примеры использования

### Создание проекта с участниками:
1. Создать проект: `POST /projects/`
2. Добавить участников: `POST /projects/{project_id}/participants`
3. Создать дополнительные workspace: `POST /projects/{project_id}/workspaces`
4. Настроить права участников: `PATCH /projects/{project_id}/participants/{user_id}`

### Получение информации о проекте:
```bash
GET /projects/{project_id}
```
Вернёт полную информацию о проекте включая:
- Основные данные проекта
- Список рабочих пространств
- Список участников
- Информацию о создателе

### Фильтрация проектов:
```bash
GET /projects/?status=active&tags=["frontend","react"]&search=диплом
```

## Обработка ошибок
Все операции возвращают стандартные HTTP коды:
- `200` - успешно
- `201` - создано
- `400` - неверный запрос
- `401` - не авторизован
- `403` - недостаточно прав
- `404` - не найдено
- `422` - ошибка валидации

## Важные ограничения
1. Максимальный размер страницы - 100 элементов
2. Минимальная длина названия проекта - 1 символ
3. Максимальная длина названия - 255 символов
4. Курс обучения участников должен быть в диапазоне 1-6
